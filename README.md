# 拾集 v1.8.22｜自動解決分筆同步衝突版

## 改好什麼

- **修正 v1.8.21 衝突永久鎖定**：不再因為一次衝突就停止每 5 秒自動同步，也不會把原本已儲存的 Worker 連線判定為需要重新設定。
- **安全合併**：同篇文章的本機備註、雲端新照片、AI 辨識、標籤、清單，可合併的會自動合併；圖片／標籤陣列採不遺失資訊的聯集。
- **保留不相容的欄位值**：同一欄的兩種值如果互斥，先將本機與雲端紀錄存到 iPhone IndexedDB 的 `safety_backups`，再把未採用的欄位值存入原記錄的 `_syncRecovered` 中，可透過 JSON 匯出查閱；無法儲存備份時不執行合併。
- **真的遇到 409 也會自動重試**：Worker 新增唯讀的 `GET /api/v2/document`，直接抓特定文章最新版本，不依賴可能已錯過變更的同步游標。單次最多重試 4 次；仍持續被其他裝置更新時，保留資料，下一次自動同步再試。
- **維持既有設定與資料**：沿用原本的 Cloudflare Worker 網址、私密密鑰 `SJ_TOKEN`、`DB`（D1）、AI 及 BROWSER 綁定。`app_state`、舊 D1 遷移備份以及 iPhone 的收藏資料不會在升級時被刪除。
- **免費原則**：不用 R2，不新增付費服務。是否完全落在免費額度內，仍取決於 Cloudflare 各項免費用量。

## 本次資料夾

- `index.html`：完整拾集前端。更新 GitHub Pages 原本的 `index.html`（保留原專案與網址）。
- `worker.js`：完整 Worker；若原本透過 Wrangler 發布，取代原 Worker 程式原始碼、沿用原有設定。
- `worker.txt`：同內容備份，適合複製貼到 Worker 編輯器。
- `tests/test-auto-merge.cjs`：自動合併、既有 hash-only baseline、多圖+備註+AI，以及 409 重試測試。
- `tests/test-migration.cjs`：D1 舊資料備份、驗證、增量儲存以及中斷測試。

## 操作順序

1. **先備份**：從現在正常顯示資料的拾集選「匯出本機備份」，下載並保存 JSON，檔案不要刪除。
2. 在原本 **Cloudflare Worker** 更新程式碼，使用 `worker.js`（**不要建立新 Worker 或新資料庫**），保留原本的 D1、AI、BROWSER、`SJ_TOKEN` 及設定。
3. 然後到原本的 **GitHub Pages** 專案更新 `index.html`。不要重新建置網站、不要變更網址。
4. iPhone 開啟既有拾集網址，重新載入一次，版本應為 **v1.8.22**。舊有 Worker URL 和密鑰存在 iPhone 網站儲存空間，**不需要再輸入**。
5. 在「雲端同步」按「立即同步」；正常更新差異會自動安全合併。可到「檢查同步原因」查看雲端修訂號是否再增加，並抽查文章、圖片、備註和清單。

**嚴禁做的事**：不要清除 Safari 網站資料、不要刪除 D1、不要在沒有匯出備份前切換到其他完全不同的同步帳戶。已部署的舊版前端若有另一裝置同時使用，建議也重新載入更新版本。

## 驗證與限制

這份檔案通過 JavaScript 語法檢查及 Node/SQLite 離線模擬測試。由於沒有授權中的 Cloudflare／GitHub 部署連線，**目前尚未部署你的正式網站，也沒有讀取或修改你的真實 D1**；不能宣稱這一刻你看到的衝突已在雲端消失。部署後仍須在實際手機與 D1 上驗證。

當兩台裝置同時修改同一備註為不同文字，程式無法知道你最終想採用哪一段：為了不再跳衝突，會採用手機當下值作為主值，雲端不同文字保留在 `_syncRecovered` 和安全備份中，而不是靜默丟掉。若瀏覽器無法寫入安全備份，會停止該次自動合併而不是冒險覆蓋。
