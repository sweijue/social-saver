# 拾集 v1.8.21｜免費長期儲存優化版

## 套件內容
- `index.html`：完整 GitHub Pages 前端（不是補丁，保留既有畫面、收藏、分類、清單與自動擷取）。
- `worker.js` / `worker.txt`：同一份完整 Cloudflare Worker 程式碼（依你慣用的部署入口擇一使用）。
- `tests/test-migration.cjs`：離線資料遷移與增量同步測試。

## 重要：現在尚未部署到現有服務
沒有修改 GitHub、Cloudflare、D1，也不需要更換原有 Worker 網址、D1、DB/AI/BROWSER 綁定或 SJ_TOKEN。
**現在請先使用目前正常的版本。不要清除 iPhone Safari 的網站資料，也不要刪除 D1 資料庫。**

## 安全機制
1. **雲端備份先行**：移轉前保留原本 `app_state`，另存一份帶 SHA-256 的不可覆寫 `sync_legacy_backups`。
2. **本機備份**：在原有 IndexedDB 增加 `safety_backups`，先保存一份本機收藏快照（不刪原有 `state`）。
3. **分筆暫存**：依舊版 revision 分批寫入 `sync_migration_stage`；不動舊收藏、不刪除暫存。
4. **內容驗證**：比對文章／購物清單／旅遊清單／設定等每一筆原始 JSON，而不是只比對數量。期間若舊版變動會停止或重新暫存，絕不猜測誰的資料較新。
5. **最後切換**：全部內容確認相同、來源 revision 不變後，才將 `sync_control.active` 啟用，留下驗證稽核紀錄。
6. **增量同步**：後續依每筆版本／全域游標同步，單筆衝突會停下並保留兩端資料，不整包覆蓋；遠端變更先在暫存物件中確認無衝突，再一次儲存本機。
7. **不新增付費依賴**：不使用 R2，不需信用卡或訂閱。沿用既有 D1、Workers AI、Browser Run；用量仍受到各服務免費額度與日後政策變動影響。

## 受控部署順序（準備正式更新時再操作）
1. 使用目前版本的「匯出備份」下載一份 JSON 放在 iPhone「檔案」或電腦。確認備份可開啟。這是一份跨裝置的額外保障，不要只依賴同一個 D1。
2. 保留原始 `index.html` 與 Worker 程式碼一份；不要更換 Cloudflare 環境變數、連線網址與資料庫名稱。
3. 先更新既有 `shiji-sync` Worker 程式（不要建立新 Worker，不要刪 DB）。舊前端此時仍可沿用既有 `/api/state`，新表只做加法建立。
4. 再更新 GitHub Pages `index.html`；原 iPhone 站點開啟後會沿用本機已儲存的網址與密鑰，先做本機和 D1 安全備份、分批移轉、逐筆驗證，再啟動增量同步。
5. 在「雲端設定 → 檢查同步原因」確認「遷移備份已驗證」及收藏數量，抽查多圖、AI 文字、分類、備註、購物與旅遊清單。若失敗，先保存備份與錯誤訊息，不清除網站資料、不刪資料庫，也不要盲目覆蓋遠端。

**限制**：本套件經離線模擬測試，但尚未連接你的實際 Cloudflare D1 做完整資料驗證；正式切換前須核對真實資料與持有的獨立 JSON 備份。資料安全措施能降低風險，不能保證第三方服務永久免費、圖片來源 URL 永遠有效或避免所有裝置損壞。
