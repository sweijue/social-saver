拾集 v1.8.22 - 修正雲端同步卡住 / 新文章沒進來

重要：本修正保留原來 Cloudflare D1 資料庫及備份，不使用 R2。
原來的 v1.8.21 具有分筆同步架構，這個修正版先修復其中的收件及等待問題；不會清除 D1，也不會強制退回舊版資料格式。

操作順序：
1. 在 iPhone 桌面「拾集」App：進入側邊選單 > 匯出備份，把 JSON 保存在「檔案」App（建議先做）。不要刪除桌面 App。
2. GitHub Pages 專案 social-saver：以這份 index.html 完整取代專案根目錄的 index.html；不用加入其他檔案，也不要把雲端密鑰放在 GitHub。
3. Cloudflare：在你原來的 Worker 專案，把原 Worker 程式換成 worker.js 的完整內容，使用原來的部署方式（例如 Wrangler deploy）。不要重建 D1，不要修改 SJ_TOKEN、DB、AI、BROWSER 綁定。
4. 確認 Worker /health 回傳 version 1.8.22，再開啟桌面「拾集」，確認頁面版本 1.8.22。
5. 從社群分享一篇測試文章到原本的 iPhone 捷徑，再到桌面「拾集」看文章是否進來。若雲端失敗，新增的文章仍會先保存在這台裝置；不要刪除 App 或清除網站資料。

本版修正：
- 從雲端收件匣先讀取新收藏並在本機安全保存，再處理舊同步工作。
- 即使雲端同步失敗，也不會先將新收到的文章標記為已送達。
- 分筆上傳一次不超過 8 筆，避免單輪太久；尚未完成會續傳。
- 已有的分筆移轉若尚未完成，每輪處理少量並記錄續傳位置，避免長時間卡住或從頭開始。
- 減少 Worker 重複建立資料表的 D1 查詢量。
- 首次讀取舊雲端資料時，不直接整份覆蓋本機文章；同 ID 衝突時以保護資料為優先。

驗證範圍：已檢查完整 HTML/Worker JavaScript 語法；以模擬環境測試新文章在同步失敗時依然保存、同步成功後才確認收件。尚未直接登入或改動你的 Cloudflare D1；實際裝置仍需以一篇測試收藏驗證。
